level 2 · a RIM machine
Scope

BigMo is a RIM machine — an implementation of Recursive Integration, not a design produced by one. It is the substrate its Scoots execute on: the assistant, its services, and the shared artifacts that let several agents work one tree without destroying each other's information at the hand-off.

What would make it a RIM machine

One shared artifact

An append-only event log as sole truth; current state a fold over it, never a cached snapshot.

Positional authority

The owner of a file is the session whose working directory contains it — never a session name. Names drift; directories don't.

Non-blocking hand-off

Contended resources have one writer. Others don't wait — they hand off a payload and keep authoring.

Recursive improvement

The machine is built to build its Scoots; improving a Scoot's process improves the machine.

Four meets, three partial, one fail — rescored 2026-09-15 against the host, from four meets and three fails a week earlier. Three concrete gaps were closed the same day (the deferred slot, dependency-absence logging, and the incomplete session registry); whether any of them moves a verdict from partial to meets is deliberately left to the pattern document's author, because scoring your own machine upward is the one direction that needs an outside check. Phase 2 of the instantiation handoff moved exactly the two the bundle predicted would move, 3.2 and 3.3, and it moved them to partial rather than to meets: a map that is consulted but not enforced, and a log that is authoritative for the machine but not for the designs on top of it. The one outright fail is the one concurrency has not yet forced — one author, one tenant. That is a reason not to buy it early rather than a deficiency, and this table is supposed to keep moving.
