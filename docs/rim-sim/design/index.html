Player-card pipeline

level 3 · a RIM design
Scope

Player-card pipeline is a RIM design — work executed on a RIM machine. A design is not merely produced by the pattern; it occupies positions 1 and 2 of the chain one turn down, which is why a design is literally a RIM instance rather than an analogy.

Its Map and its Model

Map — positional truth

The card_art table: every source photo and every render stage is a hash-addressed row with parent_hash lineage and a status (received → rendering → rendered → approved / rejected). Position, not name, says what a file is. — where this design's parts actually are, and who may write them.

Model — the account

render_card_photo.py: raw (Kontext + PuLID) → jersey composite → figure → 300 dpi card front. Each stage predicts the next from the previous; every intermediate is persisted, so a stage can be re-run without re-running the ones before it. — the artifact that predicts, or that is the design.

The invariant to hold yourself to: these two must be the same artifact. If the Map lives in one place and the Model in another, the hand-off loss has already been taken — and that is the failure the whole pattern exists to prevent.
