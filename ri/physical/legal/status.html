Repositories

scoot /home/brandon/scoot

The main platform: React client, Node/Express API, Postgres schema, and the (not-yet-started) C core. Thin client, heavy server — the client renders and calls the API, all business logic lives server-side.

Client: React 18 + TS + Vite + Tailwind/shadcn Server: Node/Express + TS + Drizzle 19 migrations 8 route modules 11 pages

scoot-chat /home/brandon/scoot-chat

Standalone shared chat-UI package — room list, message thread, input, media, WebSocket hook. Bind-mounted straight into the scoot app container (no publish/install step; edits are live via Vite/tsx watch). Also consumed by the separate Steve project as an installed dependency.

React components + useChatSocket hook Native (.native.tsx) variants for the future mobile app

scootchain (prototype) /home/brandon/scootchain

Early standalone C proof-of-concept, predating Phase 5 scoping: key generation using a post-quantum signature scheme (ML-DSA-87 via liboqs, the Open Quantum Safe library) rather than classical ECC. Not yet integrated into scootd — the live input to Phase 5's wallet/crypto design, not a running service.

memory-vault (third-party) /home/brandon/memory-vault

Postgres + pgvector semantic-memory server (MIT-licensed, upstream mihaibuilds/memory-vault). Runs two ways: as an MCP server for Claude Code's own project memory, and as a REST backend BigMo (the SMS bot) calls for long-term recall — a vault outage degrades to a no-op rather than ever blocking an SMS reply.

scoot-chat sync check

The dreamlab checkout of scoot-chat is on main, clean, and matches origin/main exactly as of the last check — nothing ahead or behind. If work done elsewhere hasn't been git pushed yet, this checkout won't have it until it is; the bind mount means once it's pushed and pulled here, the running app picks it up immediately with no rebuild.
